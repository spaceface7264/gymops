# Facelift Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give the existing GymOps screens a visual identity (All Gravy feel, the icon violet, Inter, light only) without changing layout, navigation or routes.

**Architecture:** Tokens first in `src/index.css` so every screen shifts at once; then the ten vendored shadcn primitives; then a small shared layer (`Logo`, `PageHeader`, `EmptyState`, `LoadingState`, `StatusBadge`) that the shell and the screens are swept onto. Each task leaves the app working and the gates green.

**Tech Stack:** React 19, react-router 7, Tailwind v4 (CSS-first, no config file), shadcn new-york primitives on the unified `radix-ui` package, `class-variance-authority`, lucide icons, i18next, Vitest + Testing Library, Prettier + ESLint.

Spec: `docs/superpowers/specs/2026-09-03-facelift-design.md`. Task IDs P7C-01 … P7C-05 in `PROJECT_TASKS.md`.

## Global Constraints

- No hard-coded UI strings; every new key exists in both `src/locales/en/common.json` and `src/locales/da/common.json`. Danish runs long.
- Layout and routes unchanged: bottom tab bar on phone, sidebar from `md` up, `fullBleedRoutes = ['/chat']`.
- Touch: 44 px minimum hit area on phone controls.
- `@tauri-apps/*` only under `src/lib/platform`. Fonts must ship in the bundle (self-hosted, no Google Fonts).
- Light only. No `.dark` block, no `dark:` classes anywhere in `src/`.
- Colour values exactly as tabulated in spec §3. Violet is never body text on white.
- Gates after every task: `npm run typecheck && npm run lint && npm run format:check && npm run test`. `npm run build` at the end of each P7C task.
- Commit messages reference the task ID, e.g. `feat(ui): violet tokens and Inter (P7C-01)`. Attribution trailers per the session's git rules.
- Finishing a P7C task means updating `PROJECT_STATE.md` (task row + phase row) in the same commit; `PROJECT_SPEC.md` §3.2/§4 only where a decision changes (the dark-mode removal and the shared layer belong in §4 rejected options / §3.2).
- Work happens on branch `facelift` in the worktree `.claude/worktrees/facelift`.

import type { ReactNode } from 'react'
import { Badge } from '@/components/ui/badge'
import { cn } from '@/lib/utils'

export type Tone = 'success' | 'warning' | 'info' | 'danger' | 'new' | 'neutral'

const toneClasses: Record<Exclude<Tone, 'neutral'>, { badge: string; dot: string }> = {
  success: {
    badge: 'bg-tone-success-bg text-tone-success-fg',
    dot: 'bg-tone-success-dot',
  },
  warning: {
    badge: 'bg-tone-warning-bg text-tone-warning-fg',
    dot: 'bg-tone-warning-dot',
  },
  info: { badge: 'bg-tone-info-bg text-tone-info-fg', dot: 'bg-tone-info-dot' },
  danger: { badge: 'bg-tone-danger-bg text-tone-danger-fg', dot: 'bg-tone-danger-dot' },
  new: { badge: 'bg-tone-new-bg text-tone-new-fg', dot: 'bg-tone-new-dot' },
}

/**
 * One badge for every state the app shows: tinted background, dark text of
 * the same hue, a dot. `neutral` is the quiet outline for labels that are not
 * states at all — a gym name, a kind.
 */
export function StatusBadge({
  tone,
  dot = tone !== 'neutral',
  className,
  children,
  ...props
}: React.ComponentProps<'span'> & { tone: Tone; dot?: boolean; children: ReactNode }) {
  if (tone === 'neutral') {
    return (
      <Badge variant="outline" className={className} {...props}>
        {children}
      </Badge>
    )
  }
  const classes = toneClasses[tone]
  return (
    <Badge variant="ghost" className={cn(classes.badge, className)} {...props}>
      {dot && (
        <span aria-hidden="true" className={cn('size-1.5 rounded-full', classes.dot)} />
      )}
      {children}
    </Badge>
  )
}

### Task 6: Sweep — login, home cards (P7C-05, part 1)

The sweep pattern, applied in every part below:

1. A screen that renders its own `<h1 className="text-2xl font-semibold">` gets `<PageHeader title=… action=… />` instead, with the page's primary button (the `Link`/`Button` that today sits next to the title) as `action`.

4. Badges: `Badge variant="destructive"` for a bad state → `StatusBadge tone="danger"`; `"secondary"` for an in-progress state → `"warning"` or `"info"`; `"outline"` for a done state → `"success"`; `"outline"` for a label (gym, kind) → `"neutral"`; `Badge` default for "new / unread / must acknowledge" → `"new"`.
5. Every `<a>`/`Link` that is an action gets `Button asChild` so it is a pill; inline text links keep `underline`.
